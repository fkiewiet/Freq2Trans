# Logbook — 2026-04-23
# Warm-Start FGMRES Experiment

---

## 1. What this experiment is about

**Scientific question:**  
Does using the frequency-transfer network as an initial guess for FGMRES reduce the number of iterations needed to solve the high-frequency Helmholtz system?

Concretely: given a low-frequency Helmholtz solution `u_low` (at ω=16), the network predicts `û_high = T(u_low)` at ω=32. We test whether starting FGMRES from `x₀ = û_high` is faster than starting from `x₀ = 0`.

This is a **warm-start experiment**, not a preconditioner experiment. The network is not used as a preconditioner — it is only called once to produce the initial guess, and then FGMRES runs normally.

**Why this matters:**  
Solving A(ω_high) x = f via direct sparse solve (UMFPACK) for a 512×512 Helmholtz system takes hours. FGMRES is cheaper per iteration. If the warm start cuts the number of FGMRES iterations significantly, the combination [cheap low-freq solve + network + fewer FGMRES iters] can beat [cold-start FGMRES] on total time.

## 2. Pipeline (matching the architecture diagram)

```
Source f_i generated
  (complex Gaussian, 3–6 sources, amplitudes in [1,2], random phases)
         │
         ├──────────────────────────────────────────────────┐
         │                                                  │
    UMFPACK solve:                                    Source used directly
    A(ω=16) u_low = −f_i                             as RHS for FGMRES
         │
    Network:
    û_high = T(u_low / rms) * rms
    (PML border zeroed)
         │
    FGMRES on A(ω=32) x = −f_i:                  FGMRES on A(ω=32) x = −f_i:
    x₀ = û_high  [Method W]                       x₀ = 0  [Method A]
         │                                                  │
    Record ‖r_k‖/‖b‖ over iterations             Record ‖r_k‖/‖b‖ over iterations
         └──────────────────────────────────────────────────┘
                               Compare curves
```

**Key quantities:**
- `r₀ ratio = ‖b − A_H û_high‖ / ‖b‖` — how much the warm start reduces the initial residual. Values < 1.0 are GOOD; it means the network prediction is already partway to the solution.
- Residual axis: `‖r_k‖ / ‖b‖` (both methods normalised by the same `‖b‖`).
- Convergence target: `tol = 1e-6` (i.e., `‖r_k‖ < 1e-6 · ‖b‖`).

## 3. Key physics facts — READ THIS

**Grid:**  512×512, PML depth = 112 cells, interior = 288×288, `dx = 1/287 ≈ 0.00348`

**Why dx matters (a past bug):** An earlier version used `dx=1` (wrong). With `dx=1`, the Helmholtz matrix is nearly diagonal (k²=1024 >> 4/dx²=4), so FGMRES "converged" in 2 iterations trivially — it was not solving a real wave problem at all. With the correct `dx=1/287`, the Laplacian term dominates (4/dx² ≈ 329,000 >> k²=1024) and FGMRES needs many iterations, which is the correct physics.

**Sign convention:** The Helmholtz equation is `(Δ + k²) u = −f`. The FD matrix `A` represents `(Δ + k²)`, so the FGMRES right-hand side is `b = −source_field` (negative of the source). An earlier version used `+source`, which caused the warm start to point in the wrong direction.

**Dataset normalization:** The network was trained on `u_low / rms` (where `rms` = interior RMS of `u_low`). Before feeding to the network, always normalize. After the network outputs, multiply by `rms`. Interior of u_low should have `‖u_low_interior‖_rms ≈ rms`.

**PML zeroing:** The network was trained with interior-only loss. Its output in the PML border (outer 112 cells) is meaningless. Always zero those 112 cells on all 4 sides of `û_high` before using as `x₀`.

## 6. How to interpret the results

**Open:** `convergence.png` — one panel per test problem. Both residual curves start and we see how many iterations each needs.

**The key number in `summary.txt` is `r0_ratio`:**

| r₀ ratio | Interpretation |
|---|---|
| < 1.0 | ✅ Warm start is GOOD — network prediction closer to solution than zero |
| ≈ 0.1 | 🎉 Excellent — 90% of FGMRES work eliminated upfront |
| > 1.0 | ❌ Warm start makes things WORSE — something is wrong |

**If `r₀ ratio < 1` but FGMRES doesn't converge in 500 iterations:**  
That's still a valid and publishable result. It means the warm start reduces the initial residual (the "quality" of x₀ is good), but unpreconditioned FGMRES on Helmholtz at ω=32 is slow regardless. You'd then add a CSL preconditioner to show full convergence (future step).

**If `r₀ ratio > 1` (warm start worse):**  
The network prediction is not close enough to `u_high_FD`. Possible reasons:
- The network was trained on Green's function solutions; the FD+PML solution differs in PML region (interior should still match well — check field plots)
- The distribution shift from Green's function training to FD testing is too large

## 7. History of bugs fixed (so you don't re-introduce them)

| Bug | Symptom | Fix |
|---|---|---|
| `dx=1` in FD matrix | FGMRES converged in 2 iterations for ALL samples, same final_rel 9.66e-8 | Use `dx = 1/(INTERIOR-1) = 1/287` |
| Wrong RHS sign | r₀ ratio ≈ 2.0–2.5 (much worse than baseline) | RHS `b = −source_field`, not `+source` |
| Missing PML zeroing | r₀ inflated by garbage in PML border | Zero outer 112 cells of `û_high` after network call |
| Missing normalization | Network fed raw u_low (not in training distribution) | Divide by rms before network, multiply after |
| Used ILU instead of LU | User rejected — scientifically weaker | Always use `spla.splu()` (exact), never `spla.spilu()` |
| Dataset source mismatch | source_re.npy only stores Re(source) — complex source lost | Generate fresh Gaussian sources (complex) instead of loading from dataset |
