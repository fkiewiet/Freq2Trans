Freq2Transfer

Frequency-transfer neural operators for Helmholtz preconditioning. This page is organized to answer three questions quickly: what the models take in and produce, what the CNN and U-Net are doing internally, and why flexible GMRES is the right outer solver for the neural preconditioner experiments.

Research Goal

Learn a transfer map T_{omega_L -> omega_H} that sends a low-frequency Helmholtz field to the corresponding high-frequency field for the same source pattern, then use that map inside a right-preconditioned Krylov solve for A_H x = b.

What Matters First

The project is not "training a generic image model." It is trying to learn an operator that preserves source geometry while changing frequency, then use that operator inside a hard indefinite linear solve. The page below separates those ideas so the logic is easier to follow.

1. What goes into the network?

A 29-channel tensor on a 512 x 512 grid: real and imaginary parts of u_low, a PML map, 24 Fourier positional channels, a normalized frequency scalar, and a direction bit.

2. What comes out?

Two channels: the predicted real and imaginary parts of u_high. Training uses interior-focused normalization so the trivial zero predictor is exactly 100% RelL2.

3. Why is GMRES involved?

The learned transfer map is not the final answer. It becomes one stage of an approximate inverse that is applied at every Krylov iteration, so solver behavior depends on both model accuracy and algorithmic compatibility.

Interactive Flexible GMRES Explainer

If the neural preconditioner feels abstract, the key idea is this: GMRES builds a subspace of residual directions, while FGMRES also stores the preconditioned vectors that generated those directions. That extra bookkeeping is what makes it "flexible."

1. Start from the residual

FGMRES normalizes the current residual and uses it as the next Krylov basis vector v_j.

Residual basis v_j
normalized residual direction
Preconditioner apply z_j = M_j^{-1} v_j
High-frequency operator w = A_H z_j
Arnoldi step orthogonalize w against prior v_i
Small solve choose coefficients y that minimize residual
State update x = x_0 + sum y_i z_i

What to remember

The residual is the direction in which the current solution is still wrong. GMRES starts by asking: "which correction directions are worth exploring next?"

  • Standard GMRES stores basis vectors v_1, v_2, ....
  • FGMRES stores both v_j and the preconditioned vectors z_j.
  • This matters when the preconditioner is variable, approximate, nonlinear, or changes in effect across iterations.

What "flexible" means in one sentence

In standard right-preconditioned GMRES, one fixed linear map M^{-1} is assumed everywhere. In FGMRES, the effective preconditioning action may differ from step to step, so the algorithm keeps the actual corrected vectors z_j = M_j^{-1} v_j and uses those in the final update.

Your specific neural preconditioner, unpacked

In these experiments, a single preconditioner application is not one cheap matrix multiply. It is a pipeline: restrict to the interior, map high to low frequency with T_down, solve approximately at low frequency, map back with T_up, then pad back into the full grid.

  1. Take the current basis vector or residual-like direction in the high-frequency space.
  2. Restrict to the interior where the learned operator is defined.
  3. Apply T_down to guess the corresponding low-frequency field.
  4. Apply the low-frequency inverse surrogate, such as ILU on A_L.
  5. Apply T_up to lift the correction back to the high-frequency space.
  6. Return that corrected vector to FGMRES as z_j.

Experiment Timeline

The experiments below are rewritten as short decision points: what was tested, what was learned, and how it changed the next move.

Exp 0 - Saturation curve: can the model learn at all?

Early March 2026

Training on Green's-function data with N in {150, 300, 600, 1200} per pair showed clear improvement over the trivial baseline. The best run reached 59.0% RelL2 in the down direction and 65.5% in the up direction at N = 1200.

Takeaway: the model is learning something real, but the saturation point has not been reached, so data scale and architecture still matter.

Exp 1A - Identity task: is the architecture the bottleneck?

2026-03-13

When the target equals the input frequency, the network nearly solves the task on the real channel: 2.5% RelL2 at N = 150. The imaginary channel stayed near 53%, but that was traced to a missing loss weight, not representational failure.

Takeaway: the architecture can fit a simple map. The hard part is the actual frequency transfer, not basic capacity.

Exp 1B - Amplitude ablation: is the singularity necessary?

2026-03-13

Replacing the Hankel Green's function with a phase-only version removed the 1 / sqrt(r)-type amplitude cue. Training then flatlined at 100% RelL2 in both directions.

Takeaway: amplitude structure is not decorative. It appears necessary for source localization and decomposition.

Exp 1C - Superposition test: is the learned operator linear?

2026-03-13

Variant A reported a large superposition error, roughly 30-38%, which initially looked incompatible with preconditioning. Spatial residual maps then pointed to a global rescaling artifact caused by incorrect normalization of the summed input.

Takeaway: the bad number is likely a normalization bug, not proof of deep nonlinearity. Variant B is still the decisive follow-up.

Exp 2 - Pipeline rebuild: larger dataset and better training loop

2026-03-16

The training pipeline was rebuilt around RMS normalization, an explicit imaginary-channel term, cosine annealing with warm restarts, and longer patience. Datasets at N = 4800 per pair were generated for both directions.

Takeaway: infrastructure is now in place for the real scaling test, but the key measurement is still pending: does larger data push transfer error far enough down?

Exp 3 - Complex RRMSE loss: a cleaner objective

2026-03-19 to 2026-04-03

The old loss treated real and imaginary parts as separate channels. The new loss combines them into one complex RRMSE, which is rotation-aware and removes the need for a manual lambda_imag hyperparameter. Early runs produced 82.4% and 84.6% validation RelL2 for one up/down pair with small kernels and limited training.

Takeaway: the new loss is mathematically cleaner, but the first runs are not yet competitive with the earlier best CNN numbers, so the verdict remains open.

Exp 4 - GMRES / FGMRES benchmark: does the neural preconditioner help?

2026-03-13 to 2026-04-04

At omega = 16 -> 32 with N = 4800 weights and up to 1000 Krylov steps, none of the tested preconditioners converged to 1e-4. The neural option stalled near 0.999 final residual, while plain GMRES ended near 0.181 and ILU near 0.158.

What To Do Next

The next steps are mostly about reducing uncertainty in the right order.

Highest-priority measurements

  1. Run the real N = 4800 saturation curve and check whether RelL2 drops materially below the current plateau.
  2. Finish Superposition Variant B with correct combined normalization.
  3. Test the preconditioner on a smaller grid to separate solver difficulty from preconditioner design flaws.

Interpretation guardrails

  1. A cleaner loss is not enough by itself; the outer criterion is solver usefulness, not aesthetic training curves.
  2. If InstanceNorm breaks scale equivariance, transfer accuracy and preconditioner compatibility can both suffer.
  3. If the neural inverse remains approximate at the wrong scale, FGMRES may legitimately do worse than plain GMRES.
