## Results so far — three experiments

### Exp 1A — Autoencoder (train5)
**What it tests:** Set target = input (same ω in and out). Does the model learn
to represent wavefield structure when no frequency transfer is required?

**Result so far (N=150, epoch 145, still running):**
- Real channel: val RelL2 = **2.5%** — converging strongly, all 3 omegas behave the same
- Imaginary channel: **stuck at 53%** — does not move from epoch 1

**Interpretation:**
The architecture can represent wavefield structure with high fidelity for the
real part. The imaginary channel being stuck is a key finding — the loss or
normalisation is not treating Re/Im symmetrically. In a Green's function,
Re and Im are related by π/2 phase shift (Hilbert-transform-like), so if the
loss weight on the imaginary channel is too small, the model ignores it.

**What to check:** Look at the loss function weights for Re vs Im in
`train5_autoencoder.py`. The `imag` metric is logged separately and is frozen.

**Comparison to transfer task:** Transfer task best = 59–66% at N=1200.
Autoencoder reaches 2.5% at N=150. The architecture is not the bottleneck —
the frequency mapping is genuinely hard.

### Exp 1B — Amplitude ablation (train6)
**What it tests:** Replace Hankel G(r) = e^{ikr}/√r with phase-only G(r) = e^{ikr}.
Does the 1/√r amplitude singularity at the source drive per-source decomposition?

**Result (UP direction, epoch 10):**
- Phase-only: val RelL2 = **100% at every epoch** — the model learns absolutely nothing

**Hankel (train4):** converges to 59–66%

**Interpretation:**
The 1/√r amplitude peak is not just a helpful cue — it appears to be a
**necessary condition** for the model to learn anything. Without a spatially
unique amplitude marker at each source location, the model cannot decompose
the multi-source field. This is the strongest possible confirmation of the
professor's hypothesis.

Check with: `tmux attach -t train6_ablation` on wave7b.

### Exp 1C — Superposition test (eval_superposition) — COMPLETE
**What it tests:** N(f1+f2) ≈? N(f1) + N(f2). Is the learned operator linear?

**Results:**

| Direction | Pair | Mean ε |
|-----------|------|--------|
| UP | 16→32 | 38.1% |
| UP | 32→64 | 35.6% |
| UP | 64→128 | 32.3% |
| DOWN | 32→16 | 35.4% |
| DOWN | 64→32 | 33.0% |
| DOWN | 128→64 | 29.5% |

**Paper-ready linearity threshold: < 8%. We are at 30–38%.**

**Critical diagnosis — look at the spatial residual plots:**

File: `results_visuals/viz_signed_residual_*_zoom.png`

The signed residual Re N(f1+f2) − Re N(f1) − Re N(f2) shows a
**large-scale, spatially uniform pattern** — NOT concentrated near source
positions. This is the diagnostic signature of a **normalisation artifact**,
not true nonlinearity.

**Root cause:** The test uses Variant A normalisation:
- inp_super[:, 0:2] = inp1[:, 0:2] + inp2[:, 0:2]
- This gives a combined input with ~√2× higher amplitude than the training distribution
- The InstanceNorm in the model renormalises this differently than it would a
  single-source input, producing a global scaling error of ~30–40%

**What to do next:**
Run a Variant B test: normalise the combined input by the combined RMS before
passing to the model. This is the clean linearity test. If error drops below 8%
under Variant B, the operator is linear and the paper claim holds.

## How to interpret the signed residual plots

Open `viz_signed_residual_32_to_16_zoom.png`.

- **Colourmap:** seismic — blue = N(f1+f2) < N(f1)+N(f2), red = greater, white = zero
- **Markers:** × = source 1 position, + = source 2 position
- **What you see:** Large red/blue blocks that fill the entire interior, not
  localised around the source markers
- **Conclusion:** Error is global scaling, not local nonlinearity
- **If instead you saw rings or localised patterns around × and +**, that would
  indicate genuine nonlinearity and the professor's complex convolution suggestion
  would be the next step
